# Tracker × Words 专业词汇计划模板：Step 11 Gate

- 日期：2026-08-13
- 状态：本地实现，尚未部署
- 范围：Tracker 词汇中心、计划中心展示、Words plan-intent 发送事务、既有选择性云同步

## 目标

让词汇中心成为一条完整且唯一的词汇计划工作流：用户明确选择“新建”或“更新已有计划”，
确认后先保存同一条 Tracker 计划，再用这条计划的真实 ID 向 Words 发送待确认意图。
计划中心只展示和完成这条同源计划，不产生第二份数据。

## 专业模板

Tracker 计划只保存长期需要展示和统计的字段：名称、安排、目标词数、预计用时、可选开始时间
以及启用状态。学习模式只属于本次 Words 执行意图，不重复写入 Tracker 的长期计划字段；
Words 继续负责选择词书、按实际库存校正新词与复习词并由用户最终确认。

- 新建计划默认使用单次日期；
- 更新单次计划时同步更新其日期与目标；
- 更新既有每日或每周计划时保留原周期安排，本次日期只用于发送给 Words；
- 旧计划的用户说明会保留，超出既有同步上限时才回退到短说明；
- 计划中心在桌面、移动端和详情中展示目标词数、时间与预计用时。

## 写入顺序与失败恢复

1. 通过专用 `upsertVocabularyPlan` 写入或更新一条本机 Tracker 计划；
2. 在计划本机保存成功后提交该计划的本机 / 云端选择；
3. 使用真实计划 ID 作为 `sourceRef` 创建短期 Words handoff；
4. 如果计划写入失败，不发送 handoff；
5. 如果计划已保存但网络结果不确定，保留计划 ID 和 operation ID，原内容重试不会新建第二条计划或 handoff。

## 数据库与管理员影响

- 不新增表、字段、RPC、索引、计划快照、AI 文本或推荐历史；
- 新计划默认仅本机，只有用户明确选择云端时才进入既有 Tracker Phase 4B 同步；
- 跨产品只新增既有 `lexi_cross_product_handoffs` 中的一条短期小记录，并沿用既有 30 天待处理、7 天已处理清理策略；
- Supabase 的 owner-scoped RPC、RLS、配额和 Words 最终确认规则不变；
- Lexi Control 无需新增页面，继续沿用现有 Tracker 内容上云策略与 `words_plan_recommendation` AI 策略。

## 验收标准

1. 词汇中心默认清楚显示“新建词汇计划”，也能显式选择更新某一条旧计划；
2. 计划名称、日期、目标词数、预计用时、时间、学习模式和保存位置可在确认前修改；
3. AI 建议会填入目标词数、预计用时和学习模式，但不会自动保存或发送；
4. Words 收到的 `sourceRef` 一定是真实且已保存的 Tracker 计划 ID；
5. 相同内容失败重试沿用同一计划与发送编号，改变 Words 载荷后才生成新发送编号；
6. 计划中心可读地展示词数目标，既有周期计划不会被静默改成单次计划；
7. 两个仓库发布门禁与桌面、移动端验收通过，生产环境保持不变。
