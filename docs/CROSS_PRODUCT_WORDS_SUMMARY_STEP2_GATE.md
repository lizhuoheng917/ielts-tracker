# Lexi 跨产品第二步：Tracker 读取 Words 今日摘要

- 状态：本地实现，尚未部署
- 产品关系：Lexi Words 与 Lexi Tracker 保持平等、独立
- 本步目标：把第一步的零持久化摘要契约转化为可见价值，不引入跨产品写入

## 为什么这一步必要

第一步只冻结了契约和后端边界，用户还看不到两个产品之间的联系。第二步在
Tracker 的“今日学习”中增加 Words 今日摘要，让同一 Lexi 账号能看到另一
学习空间的当天云端进度，同时不把 Words 原始记录复制进 Tracker。

这一步只验证最轻量、风险最低的互通方向。计划意图、词句候选和任何目标
产品写入仍留在后续独立步骤，不能借摘要卡片自动执行。

## 数据链路与数据库占用

1. Dashboard 只在 `signed-in` 且存在当前用户 ID 时请求摘要。
2. 客户端把当前账号 ID 和本地日期传给
   `public.lexi_get_words_daily_summary`；RPC 再用 `auth.uid()` 复核账号。
3. RPC 即时聚合 Words 已有的 `study_days`、`wordbooks` 和 `words`。
4. 客户端严格校验 V1、产品、覆盖范围、日期、计数和计数关系后才渲染。
5. 摘要不进入 Zustand、localStorage、IndexedDB、Tracker 同步队列或新表。

页面挂载时最多读取一次，之后不轮询；只有用户点击“刷新摘要”时才再次
读取。摘要的持久化数据库占用仍为零。

## 页面与降级体验

- 卡片位于 Tracker 自身“今日学习概览”之后，使用 Words 原有绿色书本
  标识和独立版式，不替换 Tracker 标识，也不合并两套本地统计。
- 桌面端横向展示品牌说明与四项摘要；窄屏自动上下排列，并把四项摘要
  排为两列。
- 页面明确标注“Words 云端记录”，本机未同步的 Words 数据不会被误报为
  完整进度。
- 未登录、本地模式、后端未部署或请求失败时，Tracker 继续正常工作；
  卡片只显示说明或非阻塞重试，不弹出全局错误。
- “打开 Words”只跳转经过校验的产品根地址，不携带账号 ID、令牌、学习
  数据或未经支持的深链参数。

开发环境可用 `/?preview=words-summary` 验收成功态。该预览受
`import.meta.env.DEV` 限制，生产构建不会包含示例摘要。

## 协调发布顺序

1. 在正式 Lexi 仓库和 Tracker 仓库提交本步全部文件及各自
   `release-impact.json`。
2. 两个仓库分别运行完整发布门禁。
3. 先应用并远端验证第一步的精确 Supabase 迁移，确认本人读取、跨账号
   拒绝和零摘要持久化。
4. 只有后端验证通过后，才部署同一已验证 Tracker 提交。
5. 生产环境复测登录、摘要成功/零值/失败、手动刷新、Words 跳转、
   Tracker 本地记录和跨账号隔离。

## 本步完成标准

1. 严格解析器拒绝错误版本、错误日期和不可能计数。
2. 未登录时不调用摘要 RPC；失败时不阻塞 Dashboard。
3. 产品地址只允许 HTTPS 根地址或开发环境的 loopback HTTP。
4. 桌面和移动端无横向溢出，Words 与 Tracker 标识各自保持不变。
5. 两仓库完整门禁通过；在远端迁移与部署真正完成前保持
   `not-deployed`。
