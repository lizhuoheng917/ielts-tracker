# Lexi 跨产品第三步：Tracker 发送 Words 计划意图

- 状态：两仓库本地实现，尚未部署
- 产品关系：Lexi Words 与 Lexi Tracker 保持平等、独立
- 本步目标：把 Tracker 的词汇计划转成由 Words 用户确认的当天学习建议

## 必要性与边界

第二步的 Words 摘要只提供可见联系，不能把 Tracker 中的词汇计划带入实际
学习。第三步不共享两套计划表，也不让 Tracker 直接写 Words；它只创建一个
短期、可拒绝的计划意图，并把词书选择和最终应用留给 Words。

## Tracker 发送内容

只发送：

- 目标日期；
- 目标词数；
- Words 学习模式；
- 不含标题、备注或正文的本地计划引用；
- 客户端生成的 `operationId`。

标题、描述、学习记录、单词正文、账号 ID 和令牌不会作为业务 payload
复制到 Words。客户端严格拒绝未知字段、正文类字段、错误版本、变更后的
目标、超过 29 天的日期和超过 1000 的词数。

## 页面排布

- 入口只出现在 `vocabulary` 分类的计划详情，不影响阅读、听力、写作、
  口语或自定义计划。
- 发送弹窗沿用 Tracker 当前主题和组件，但内容按 Tracker 的计划结构排布。
- 日期、词数和模式可以独立确认；发送期间锁定表单和关闭动作，避免 UI
  显示值与实际请求不一致。
- 成功后只提示“已送达”，明确要求去 Words 选择词书并确认，不暗示已经
  修改学习数据。
- 开发预览：`/plans?preview=plan-intent`。

## 幂等、失败与低占用

- 同一打开周期内，相同内容重试复用相同 `operationId`；改变内容后才
  生成新 ID。
- 请求失败不修改 Tracker 计划，不创建本地镜像，也不阻塞其他 Tracker
  功能。
- 第三步不增加 Tracker 表、Zustand 实体、localStorage 项或同步 operation。
- 服务端复用第一步的一张受限临时表，处理后最多保留 7 天，并由现有清理
  任务回收。

## 安全与管理员复核

RPC 在 Supabase 端重新校验 `auth.uid()` 与捕获账号，表开启 RLS 且不向
浏览器授予直接表权限；客户端在 RPC 前后也确认登录账号未变化。

Lexi Control 本步为 `reviewed-not-needed`：临时意图不含计划正文，不是
需要管理员审核或配置的实体，也没有长期指标价值。增加逐用户查看会扩大
隐私面，不符合低占用目标。

## 完成标准

1. Tracker 与 Words 的 V1 契约保持一致。
2. 发送请求只包含允许字段，异常响应失败关闭。
3. Words 端必须再次预览、选词书并明确确认；拒绝、过期和离线不改数据。
4. 两仓库完整门禁与桌面/移动端页面验收通过。
5. 先远端应用并验证精确 Supabase 迁移，再部署依赖它的两个客户端。

在远端迁移和生产验证完成前，本步保持 `not-deployed`。
